# Stereo mini：正射影BMP生成の将来改善案

## 1. 目的と実施方針

**現時点では実装しない。** 現在のPython撮像プログラムを維持し、物体検出・位置検出を先に進める。視野の中心と端で物体の見かけの形状が異なる問題が実用上の障害になった場合に、本案を検討する。

狙いは、Basler Stereo mini STM-502uから取得したXYZ点群を利用して、物体を作業台の真上から見たような**正射影画像**を生成し、視野位置に依存する大きさ・輪郭の変化を軽減すること。

## 2. 現在のプログラムの仕組み

対象：`capture_stereo_mini_with_bmp.py`（今回確認した版）。

- `capture_xyz()`：`Range`コンポーネントから、画素ごとのXYZ座標を取得する。
- `save_ply()`：有限値かつ`DEPTH_MIN`～`DEPTH_MAX`にある3D点をPLY保存する。
- `save_depth_bmp()`：`xyz[:, :, 2]`でZ座標を取り出し、`BMP_DEPTH_MIN`～`BMP_DEPTH_MAX`を0～255の濃淡に変換してBMP保存する。
- BMPでは**元の画素位置を維持**しており、X・Y座標に基づく画素の再配置はしていない。

主な設定例：

```python
DEPTH_MIN = 180
DEPTH_MAX = 300
BMP_DEPTH_MIN = 224
BMP_DEPTH_MAX = 234
```

これらは保存対象や濃淡表示の範囲であり、正射影の設定ではない。

## 3. 現在の深度BMPと正射影BMPの違い

| 項目 | 現在の深度BMP | 将来の正射影BMP |
|---|---|---|
| Z座標を濃淡表示 | する | することが可能 |
| 画素の配置 | 撮像画像の行・列を維持 | 実空間のX・Y座標で再配置 |
| 画像の縮尺 | 位置・距離の影響が残る | 一定のmm/画素に統一可能 |
| 視野端の見かけの変化 | 残る | 軽減可能 |
| 隠れた面の復元 | できない | できない |

**注意：** 現在の深度BMPもZ座標を可視化しているが、正射影画像ではない。正射影は3D点の位置を別の2D座標系へ写し直す処理である。

## 4. 正射影の基本原理

まずXYZ点群からX・Y・Zを取得する。

```python
x = xyz[:, :, 0]
y = xyz[:, :, 1]
z = xyz[:, :, 2]
```

出力画像の縮尺を、例えば`0.2 mm/pixel`とすると、作業台と平行な座標系での投影位置は次のように求められる。

$$
u = \frac{X-X_{\min}}{s}, \qquad v = \frac{Y-Y_{\min}}{s}
$$

- $u, v$：正射影画像上の画素位置（実装時に整数化）
- $X, Y$：作業台基準の実空間座標（mm）
- $X_{\min}, Y_{\min}$：画像の原点に対応する座標（mm）
- $s$：1画素当たりの実寸法（mm/pixel）

カメラが作業台に対して傾いている場合は、**先に作業台基準の座標系へ変換**する必要がある。カメラ座標のX・Yをそのまま使うだけでは、作業台に対する厳密な真上視点にならない。

## 5. 将来の処理フロー

```text
Stereo miniで撮像
    ↓
XYZ点群を取得（既存のcapture_xyz）
    ↓
無効点・測定範囲外の点を除外
    ↓
必要なら作業台基準へ座標変換
    ↓
X・Yを一定mm/pixelの画像座標に変換
    ↓
重複画素・空白画素を処理
    ↓
Z値または作業台からの高さを濃淡化
    ↓
orthographic.bmpとして保存
    ↓
OpenCVで物体の領域・位置を検出
```

## 6. 実装時に検討する課題

1. **座標系の定義**：カメラ座標のZと、作業台からの「高さ」は必ずしも同じではない。作業台の傾き・設置姿勢を確認する。
2. **出力範囲と縮尺**：何mm四方を何mm/pixelで保存するか決める。範囲を広げると画像サイズと処理量が増える。
3. **複数点が同一画素に入る場合**：上から見て最も手前の点を採用するなど、用途に合うルールを決める。
4. **点のない画素**：未計測領域と背景を区別し、必要に応じて穴埋めする。穴埋めで架空の形状を作りすぎない。
5. **側面・遮蔽**：正射影でも、実際に撮影できなかった裏面や隠れた上面は復元できない。
6. **測定精度**：正射影によって縮尺の扱いは改善するが、3D計測そのものの精度が向上するわけではない。
7. **濃淡の情報損失**：8bit BMPは表示・検出用。精密な位置・高さの計算には元のXYZ浮動小数点データを使う。

## 8. 導入判断と検証方法

当面は現在の深度BMPとXYZデータで物体検出を進める。次の問題が出た場合に正射影を検討する。

- 同じ部品なのに視野中心と端で検出輪郭や面積が大きく変わる。
- 視野位置によって検出中心がずれ、位置補正が複雑になる。
- 部品の実寸法に基づく検出条件を統一したい。

導入時は、**同一部品を視野の中心・四隅に置いて比較**する。

| 評価項目 | 比較内容 |
|---|---|
| 検出面積 | 視野位置でどれくらい変動するか |
| 検出中心 | 基準位置に対して何mmずれるか |
| 輪郭形状 | 中心と端でどれくらい一致するか |
| 欠損画素 | 正射影によって穴が増えていないか |
| 処理時間 | 現場で許容できる速度か |

## 9. 結論

現在のBMP変換は**Z座標の濃淡表示**であり、正射影ではない。一方、現行プログラムはXYZ点群を取得できているため、将来の正射影処理に必要な基礎データはすでにある。

**今すぐ改造する必要はない。** まず物体検出・位置検出を進め、視野位置による形状変化が問題になった時点で、`save_orthographic_bmp()`を独立して追加する。
